## Red flags

- **A new preference, no migration.** `model_icons` is stored through the existing preferences table. The fork's first free migration number is still 067.
- **Custom icon deletion now edits two preferences.** `internal/repository/custom_icons.go` clears a deleted icon's `custom:<id>` from `provider_icons` and `model_icons` in one transaction. A fork change to either preference's shape must keep both in step.
- **Deleting a custom icon through the console is unaudited.** `deleteCustomIcon` in `internal/api/custom_icons.go` calls the repository directly, outside `internal/operations/`, with no revision check and no audit record. The handler is unchanged in this window, but the call now rewrites `model_icons` as well as `provider_icons`. Upstream's design; fixing it here would be a carried deviation.
- **The agent's icon delete may leave the identity directory stale.** Upstream's commit body asks whether the delete path publishes an identity-directory sync. The console handler does (`publishStateSync` after the delete). The `custom_icon_delete` capability in `internal/operations/custom_icons.go` only lists `custom-icons` and `preferences` as invalidated, and no file under `internal/api/agent*.go` calls `publishStateSync` or resets the identity archive (read by grep, not reproduced). The same was true for `provider_icons` before this window.
- **A tab can overwrite another session's icon choices.** A model icon pick writes the whole `model_icons` document with no revision (`useModelIconOverrides.ts`). The tab's copy is refreshed only by a sync event, and that refresh is dropped when the preferences read fails (`reconcilePreferenceKeys` in `usePreference.ts` returns from a bare `catch`) or when the event arrives while a provider or credential toggle is in flight (`useEventSource.ts` returns early). The next pick from that tab then reverts changes made elsewhere, and a missed custom icon delete makes its writes fail with `custom_icon_not_found` until reload. Read from the code, not reproduced. Worth raising upstream.
- **A non-list `requests.payload.replace` is read as empty.** `payloadRules.ts` parses a map or scalar there to no rules and flags nothing, so the first rule added in the console overwrites the original value. The five older payload categories behave the same way.
- **Upstream tests still carry Chinese input-method data.** Each new composition test brings it back, and the gate catches it. The fix is always the `\u` escape, never a `PHRASES` row.
- **The catalog conflict is permanent.** Every upstream commit that adds a console sentence conflicts in three deleted catalogs. `english-only.sh` settles it without a decision.

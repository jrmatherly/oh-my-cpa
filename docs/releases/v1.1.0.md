# Oh My CPA v1.1.0

Oh My CPA v1.1.0 is a feature release of this fork. It builds on [v1.0.1](v1.0.1.md)
and brings in upstream's work on the Insights page and on naming the client behind
each request, together with this fork's fixes to how the console reads CPA's
configuration.

## Insights

- **Token breakdown.** Insights shows how the tokens of a period divide into cache
  read, cache write, net input, regular output and reasoning, with the cache rate
  and reasoning share beside the title. A scope switch reads the page's token
  figures with cache or net of it.
- **Client ranking and filter.** A new ranking names the coding agents, tools and
  SDKs that sent the requests. Choosing a client filters the whole page, and the
  filter is kept in the address and carried into the request list. Client figures
  reach back as far as the retained request records, and the page says when a
  period is cut short by that horizon.
- **Steadier layout.** The headline figures are selectable tiles with rolling
  numbers, the rankings keep fixed places whatever the period holds, and the trend
  chart glides between drill-downs.
- **Failed refreshes are visible.** A client ranking whose refresh failed shows a
  warning with a retry above the figures it kept. On a phone, the model load profile
  sorts in both directions.

## Requests

- **Client column.** The request list's User-Agent column is now a Client column
  with the client's mark and product name. Grouping by client joins every version
  of one client. A request whose client was not recognised shows the User-Agent it
  sent, in the list, the drawer and the copied sheet.
- **Request drawer.** The route starts at the client that sent the request, and the
  caller key and client IP appear with the request's settings.
- **Export.** The JSON export adds `client_agent` and its schema is
  `omc.requests.v2`.
- **Recognition.** Codex Desktop and the first-party Codex applications are read as
  Codex CLI, and Hermes Agent is recognised in its camel-case and Codex-compatible
  forms.

## Quota

- **Reset credits.** The credential drawer lists every available Codex reset credit
  with its expiry, soonest first.

## CPA configuration reads

- **No warnings for unset paths.** The console reads OAuth model aliases, excluded
  models, stored key groups and plugin settings from CPA's whole configuration view.
  CPA no longer logs a 404 warning for each path that has never been set.
- **Fewer reads per load.** One load of the console's state fetches the
  configuration view once and shares it.

## Console

- **Stale pages recover.** A page opened before an upgrade reloads once when it asks
  for a script the new build no longer serves. A sign-in stage that fails to load
  leaves the form usable.

## Upgrade notes

- Back up `.env` and your SQLite database or volume before upgrading; refer to
  `docs/ops/sqlite-operations.md`.
- This release adds four database migrations, 067 to 070. They run on the first
  start after the upgrade and rewrite the retained request records and usage facts
  to store token parts and client attribution, so that start takes longer on a
  large database. Migrations are forward-only: returning to v1.0.1 means restoring
  the backup taken before the upgrade.
- A client that sends a bare name without a version, such as `Codex` or `copilot`,
  is recorded as not recognised from this release on and shows the User-Agent it
  sent. Its earlier requests can sit under a named entry, so that client can appear
  twice. No total changes.
- This release adds no environment variable or Compose service.
- Container images are available on GitHub Container Registry as
  `ghcr.io/jrmatherly/oh-my-cpa:v1.1.0` and `ghcr.io/jrmatherly/oh-my-cpa:1.1.0`.
